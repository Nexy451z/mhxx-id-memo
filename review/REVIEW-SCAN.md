### 3.2b 護石 hex と実セーブの突合 — PASS（最重要）

サンプルセーブの実護石レコード（650 件のうち index 224）と UI 出力を比較した。

| 項目 | 実セーブ | UI 出力 | 判定 |
|---|---|---|---|
| 20 バイト（推奨パターン） | `06 00 0A 00 00 00 00 00 00 00 00 00 4A 46 06 0A 03 00 64 01` | 同一 | **一致** |

UI の護石入力（種類=10 / スキル1=74 / スキル2=70 / ポイント=6,10 / スロット=3）に対して、
UI は `+0x0C..+0x13` を仕様どおり埋め、レア度は種類から正しく導出している
（kind 10 → rarity 100）。**護石モードは実セーブの護石と完全に一致する。**

なお、私の独立実装（`save_equip.encode_talisman()`）は
**サンプルセーブの護石 650 件すべてを再エンコードして一致**することを確認済み。

### 3.3 エンディアン — PASS

`put16()` は `b[off] = v & 0xFF; b[off+1] = (v >> 8) & 0xFF` でリトルエンディアン。
Lv5 → `0x0081`、Lv7 → `0x00C7`、着せ替え Lv2 → `0x0401` を実測で確認。

### 3.4 type / id 対応 — PASS

- 防具: `type = part_id + 1`、`id = series_id`
- 武器: `type = weapon_type_id + 7`（12 は欠番）、`id = weapon_index`
- UI は `weapon-types.csv` の `equip_type_id` を優先し、欠番を正しく飛ばす。

### 3.5 box 幾何 — PASS

- `slot_base + 0x62EE`、36 バイト × 2000 を実セーブで確認。
- UI の計算機: index 5 → `0x63A2`、ヒット `0x12C83A`（index 5）→ BOX 先頭
  **`0x12C786`**（実セーブの BOX 先頭と一致）。

### 3.6 スキャンパターンの一意性 — 実測

UI の案内文（「6 バイトは 14/19 が一意」「72 バイトが 1 ヒットで最も実用的」）は
**この実測値と一致**していることを確認した。
